### "블로그 배포 전쟁: GitHub Pages부터 Vercel까지 (feat. 요금 폭탄 방지 대책)"

안녕하세요! Next.js로 블로그 뼈대를 완성하고, 이제 마지막 단계인 '배포(Deploy)'를 앞둔 개발자입니다. 사실 이 과정에서 저 혼자 수많은 고민과 삽질(?)을 거듭했습니다. 옆 동네 AI 친구와 거의 토론 배틀을 벌인 끝에 내린 결론들을 여러분께 공유합니다.

### 호스팅 서비스 결정? 생각보다 복잡했다!

처음에는 별생각 없이 깃허브(GitHub)에 코드 올리고 GitHub Pages 쓰면 되겠지, 했습니다. 하지만 제 블로그는 게임 개발 일지이고, 게임 트래픽이 몰릴 경우를 대비해야 했습니다. 비용 걱정 없이 안정적으로 운영할 수 있는 최적의 호스팅 서비스를 찾는 여정이 시작되었죠.

고려한 서비스는 총 네 가지입니다.

1. **GitHub Pages:** 가장 기본.
2. **Netlify:** 자동 배포의 강자.
3. **Cloudflare Pages:** 무제한 대역폭의 신흥 강자.
4. **Vercel:** Next.js 공식 호스팅 서비스.

### 서비스별 장단점 비교 (feat. AI 친구와 나눈 대화)

각 서비스의 무료 플랜 기준 장단점과 배포 방식을 비교했습니다. (이 표를 만들기 위해 AI 친구를 꽤 괴롭혔습니다.)

| 항목                   | GitHub Pages                    | Netlify                   | Cloudflare Pages               | Vercel                    |
| ---------------------- | ------------------------------- | ------------------------- | ------------------------------ | ------------------------- |
| **가격**               | $0                              | $0                        | $0                             | $0                        |
| **빌드 시간**          | 제한 없음                       | 월 300분                  | 월 500회 (시간 무제한)         | 월 100시간                |
| **대역폭**             | 월 100GB                        | 월 100GB                  | **무제한**                     | 월 100GB                  |
| **DDoS 방어**          | 기본 제공                       | 내장 자동 방어            | **강력한 클라우드플레어 방어** | 내장 자동 방어            |
| **배포 방식 (자동화)** | **GitHub Actions 필요**         | **Git 푸시 시 자동 빌드** | **Git 푸시 시 자동 빌드**      | **Git 푸시 시 자동 빌드** |
| **요금 폭탄 위험**     | 낮음 (제한 초과 시 서비스 제한) | **있음**                  | **없음 (무제한)**              | **있음**                  |
| **최적화**             | 범용 정적 사이트                | 범용                      | Cloudflare 인프라              | **Next.js에 최적화**      |

### 고민의 핵심: 요금 폭탄을 피하는 법

Netlify와 Vercel은 강력한 기능과 편리함을 제공하지만, 한도를 초과하는 트래픽(특히 DDoS 공격 같은 악의적인 트래픽)이 발생하면 요금 폭탄을 맞을 위험이 있었습니다.

그래서 저는 AI 친구에게 물었죠. "요금 걱정 없이 블로그 할 방법이 없을까?"

답변은 **클라우드플레어(Cloudflare)**였습니다. 무제한 대역폭! 이 얼마나 매력적인 단어입니까!

하지만 제 블로그는 Next.js로 만들었고, Vercel이 Next.js에 가장 최적화되어 있다는 사실이 계속 마음에 걸렸습니다. 성능과 개발 경험, SEO까지 고려해야 했으니까요. GitHub Pages는 자동 배포를 위해 GitHub Actions를 따로 설정해야 하는 번거로움도 있었습니다.

### 결론: 두 마리 토끼를 다 잡는 하이브리드 전략!

고민 끝에 저는 최적의 조합을 찾아냈습니다.

1. **블로그 (Next.js):** **Vercel**에 배포합니다. 블로그는 성능과 SEO가 중요하므로, Next.js에 최적화된 Vercel의 성능을 최대한 활용합니다. Git 푸시 시 자동 빌드되어 매우 편리합니다. 일반적인 블로그 트래픽은 Vercel의 무료 한도로 충분합니다.
2. **플러터 게임:** 게임은 용량이 크고 트래픽이 몰릴 가능성이 있으므로, **클라우드플레어 페이지스**에 별도의 프로젝트로 배포합니다. 무제한 대역폭 덕분에 게임이 대박 나도(?) 요금 걱정은 없습니다. 여기도 Git 푸시 시 자동 빌드됩니다.

이렇게 하면 블로그는 최고의 성능을 내고, 게임은 안정적으로 서비스할 수 있습니다.

드디어 저만의 게임 개발 일지 블로그가 세상에 나올 준비가 끝났습니다!
